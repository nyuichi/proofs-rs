## Verification scope

Kani checks executions reachable from the selected harness under its assumptions. A successful run is evidence for that scope, not a claim about every configuration or every invocation of an API. Harness inputs, `kani::assume`, function preconditions and stubs can restrict the scope.

## Checks and bounds

The enabled checks, loop and recursion bounds, and unwinding assertions matter. Suppressing a check or bypassing an unwinding failure does not establish the corresponding unrestricted claim. Record non-default options and restrictions in the report.

## Undefined behavior

Kani detects supported classes of undefined behavior in its model. Rust support and the modeled environment have limitations; a successful run must not be interpreted as coverage of all Rust behavior or every possible platform.

## Contracts and trusted components

A `proof_for_contract` harness checks a function under its preconditions. Stubs, assumed contracts, compiler behavior and library models contribute to the trusted assumptions. The presence of a contract attribute in source does not establish that verification succeeded.

## Environment

Results apply to the checked target, features, dependencies and tool version. Report-specific assumptions and limitations remain part of the report and are not replaced by these notes.
